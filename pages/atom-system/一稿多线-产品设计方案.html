一、一句话定位

给一份讲稿，长出一条声音、一排字幕、一张大纲、一串重点、一组概念、一张亮起来的知识图谱——而讲稿本身一个字都不用改。

本产品是 Atom 标准中 M8 介质（多线讲稿页）的完整产品设计。它面向讲课、说课、口播三类场景：使用者只有一份文稿和一个主题，系统围绕这份文稿自动生产出一组相互同步的「线」，听讲的人沿时间轴前进时，各线同时联动。

二、核心理念：文稿是母线

整个产品只有一个信息源头：文稿。其余一切均由它派生：

  • 声音线：对文稿做语音合成，逐句生成音频，句的起止时刻即声音的时间轴；
  • 字幕线：文稿本就是逐句文本，与声音线天然逐句对齐——等同于视频里的字幕，只是它的「视频」还没生成就已经同步了；
  • 一切标注线：结构、重点、概念、图谱、意图……全部叠加在文稿的分句锚点上，不修改母线。

这里有一个反直觉但关键的顺序颠倒：传统做法先有录音再回头转写对齐，本产品先有文稿，声音与对齐是从文稿「正向生成」的。于是对齐精度天生就是句级，接上强制对齐后可以到字级，且永远不需要人工打时间戳。

红线：任何线都不得反向修改母线。改内容只改文稿，改完重新派生各线；在声音或标注上直接打补丁一律禁止。

母线只有一个，线有任意多条。线与线平权：可以整体删除任何一条而不影响其余；可以随时新增一条线而不动母线。

四、线协议：一条线怎么定义

这是本方案的核心抽象，已写入 Atom 规范 11.1 节。任何线必须登记六要素：

要素内容示例（重点线）
编号与名称线在注册表中的唯一标识L2 重点线
锚点粒度章 / 节 / 分句 / 字，向下兼容分句
呈现方式这条线出现时观众看到什么文字加粗与高亮
生成方式自动 / 模型候选加人工校订 / 纯人工模型候选＋人工确认
默认开关播放页初始是否显示开
依赖声明跨线依赖必须显式，禁止隐式依赖无
硬规则：线的产物落盘为独立文件；介质段装配时才合并。删一条线＝删一个文件；加一条线＝注册加落盘加装配开关。

五、内建五条线详解

L1 结构线——「我讲了哪几部分」

锚点：章、节（区间挂载）。识别整份文稿的内容分区：章与节构成大结构树，时间区间由子节点推导。呈现为左侧大纲树高亮、顶部进度条按章分段。这是唯一自动生成的线——标题层级即结构，无需智能体判断。

L2 重点线——「哪几句话特别重要」

锚点：分句。整份文稿的注意力分配：哪些句子是需要听众记住的核心论断，逐句判定重要程度（核心、支撑、过渡三级），核心句播放时加粗高亮，过渡句自动淡显。生成方式为模型逐句给出候选与理由，人只确认候选名单——校订成本远低于从零标注。

L3 概念线——「学生会在哪里卡住」

锚点：分句。难点概念探测：讲到某个学生易卡住的概念时弹出概念卡（定义、判断标准、常见误解），讲到设问处弹出问答卡。概念卡内容与弹出时机都挂在分句锚点上。此线已实现，是其余各线的原型。

L4 图谱线——「讲到哪里，点亮哪里」

锚点：分句。知识图谱联动：讲稿中每个分句与图谱节点做匹配，讲到某句时右侧图谱同步点亮所涉节点与连边，讲完一章，一章的子图已亮。它让「知识结构」从目录页的一次性展示，变成全程呼吸着的背景。生成方式为图谱匹配加人工校订；前提是主题已有图谱，没有时先由图谱构建流程补齐。

L5 意图线——「这句话为什么这样讲」

锚点：分句。教学意图标注：建立概念、制造冲突、给出类比、提示易错、要求回忆。它是给作者看的线，不上播放页——用于备课复盘与讲稿互审，也是三条生成式线（重点、概念、图谱）的依据来源：意图定了，重点与概念自然浮现。

自定义线

以上皆可按线协议扩展，例如「节奏线」（哪里该快、哪里该停）、「共鸣线」（哪里该请学生举例）、「证据线」（哪里需要出示实验或数据）。注册六要素、落盘产物、登记进规范注册表，即成为标准线。

六、线是怎么被生产出来的

输入只有两样：文稿与主题。生产按线分派给不同的智能体角色，彼此并行：

线生产者（角色）输入人做什么
结构线结构角色文稿标题层级无需介入
重点线解析角色（判读）逐句文稿＋主题确认核心句名单
概念线解析角色（教学）逐句文稿＋学情确认概念卡与时机
图谱线解析角色（关联）逐句文稿＋知识图谱校订节点匹配
意图线纯人工作者本人写（这也是其他线的校订依据）

注意生成顺序上的一个设计：意图线虽是纯人工，却建议先写——作者标完意图，重点线与概念线的模型候选就有了依据，确认成本大幅下降。意图是其他线的纲。

七、呈现规范：播放页与静态退化

播放页（动态形态）

  • 母线居中：逐句滚动，当前句高亮，声音线同步播放；
  • 结构线居左：大纲树实时指示位置，可点击跳转；
  • 其余线居右或内嵌：概念卡弹出、重点句加粗、图谱点亮；
  • 每条线有独立开关；进度条按章分段（结构线的可视形态）。

静态退化（打印形态）

打印为静态介质时各线不消失，而是退化：重点线退化为加粗，概念线退化为页边卡片，结构线退化为目录，图谱线退化为文末附图，意图线退化为批注样式。一份文稿、一套数据，两种形态。

八、与 Atom 五段信息流的映射

段本产品的工作产物落盘
源段文稿与主题就位文稿原文
解析段切章、切节、切分句，建锚点系统母线结构树
加工段各线智能体并行生产，各自落盘每线一个独立文件
介质段装配播放页：母线＋已开关的线单文件多线讲稿页
确认段台面逐线验收：每条线一个勾选清单验收留痕

加工段的并行是效率关键：五条线互不依赖，可同时生产；某条线失败只重跑该线，不影响其余。这正是线协议「禁止隐式依赖」换来的工程红利。

九、演进路线

阶段内容状态
第一阶段结构线＋概念线，演示播放页已完成
第二阶段线协议入规范；重点线（加粗高亮）与逐线开关上线规范已完成，播放页待升级
第三阶段语音合成接入：声音线与字幕线正向生成，锚点精确到真实语音待启动
第四阶段强制对齐：锚点从分句下沉到字级，重点线可只加粗关键词待启动
第五阶段图谱线：主题图谱构建＋分句匹配点亮待启动
第六阶段上游备课技能：主题加思路，自动产出带意图标注的初稿待启动

十、风险与边界

  • 线不是越多越好。每条线都消耗观众注意力，播放页同屏激活的线不宜超过三条；其余默认关闭，按需打开。
  • 候选质量依赖学情输入。重点线与概念线的模型判断若无学情描述，只能按通用规律猜；输入里应包含「给谁讲」。
  • 图谱线必须有真图谱。没有图谱硬做匹配，会产出似是而非的点亮效果，宁可暂缓。
  • 意图线不可代劳。「这句话为什么这样讲」是作者的专业判断，模型可以建议，但该线必须人工落笔——这也是本产品守住「判断权在人」的位置。
